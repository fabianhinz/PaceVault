# Round 2: every feature moves into `components/`, each mounted feature gets its entry

Read `tdr/index-modules-are-not-barrels.md` first (R1, R5: an `index.tsx` declares the one entry component of a directory rendered as a unit; no `index.ts` barrels), then `tdr/component-declaration-shape.md` R6 (the entry is named for its directory in PascalCase, importers name the index). This file carries the first half of the owner's review finding R1 (`tools/workbench/backlog/conventions-migration/review/findings.md`, settled 2026-10-26): `apps/web/src/features/` disappears, every feature directory moves to `apps/web/src/components/<feature>/`, every feature a page mounts as a unit gets an `index.tsx` entry so the pages become thin `<X />` mounts, and the loose shared UI at the top of `components/` is grouped into topic directories. The `lib/` half of R1 is the next plan (`round2-lib-topic-folders`); the rule texts, the CLAUDE.md files and the boundary gate are plan 5 (`round2-rules-and-gates`).

Pure moves, renames and import rewrites: behaviour and pixels stay identical, no spec changes its assertions. The five hand-built controls (`StepButton`, `TripFormDialog`, `PaceEstimateButton`, `StudioColorPicker`, `StudioMarkerPins`) stay feature components and simply move with their feature (owner, findings R2: "They should just be moved to the components dir (colocated)").

How every move item works (run from the repo root):

- Move with `mv`, never `git mv`; nothing is staged. Create a missing target directory with `mkdir -p`.
- Every import of an app module is an `@/` path (`@/features/<x>/…`), so a feature move is one textual rewrite of `features/<x>/` → `components/<x>/` over the code files of `apps/web/src`, `apps/web/tests` and `apps/web/e2e` (`rg -l "features/<x>/" apps/web/src apps/web/tests apps/web/e2e --glob '!*.md'` lists them; rewrite each hit, e.g. with `sed -i '' 's#features/<x>/#components/<x>/#g'`). The pattern ends in `/`, so `features/map/` never touches another directory. It also rewrites `vi.mock('@/features/<x>/…')`. The `map` feature's target folder is `components/mapBackground/` (Q32), so its pattern is `features/map/` → `components/mapBackground/`.
- Kept files stay put: move every entry of `apps/web/src/features/<x>/` except the kept files (e.g. `find apps/web/src/features/<x> -mindepth 1 -maxdepth 1 ! -name <kept> … -exec mv {} apps/web/src/components/<x>/ \;`; a subdirectory holding a kept file, such as `sessions/hooks/`, is moved file by file), likewise for the specs. The rewrite gets a second expression that restores the kept paths, e.g. `sed -i '' -E -e 's#features/map/#components/mapBackground/#g' -e 's#components/mapBackground/(gpsBuild\.worker|gpsBuildContract|previewDrawIn)\.ts#features/map/\1.ts#g'`. So the dynamic `import('@/features/demo/demoRoutes.json')`, the two worker URLs (`'../../features/…'`) and every import of a kept file keep their `features/` path until plan 4.
- Markdown files are never rewritten here (`--glob '!*.md'`): the CLAUDE.md files and TDRs get their new paths in plan 5 (Open items).
- Specs mirror their subject (`tdr/mirrored-spec-layout.md` R2, R5): `apps/web/tests/features/<x>/` moves to `apps/web/tests/components/<x>/` in the same item as its feature.
- A new `index.tsx` entry is `export const <Name>: FC = () => …` (no props, like `features/onboarding/index.tsx` today), imports every module by its `@/components/…` path (index-modules R4) and takes the page's body verbatim: same hooks, same constants, same markup. The page then shrinks to the shape `apps/web/src/pages/OnboardingPage.tsx` has today:

  ```tsx
  import type { FC } from 'react';
  import { Dashboard } from '@/components/dashboard/index.tsx';

  export const DashboardPage: FC = () => <Dashboard />;
  ```

- After each item: its Check, then `vp run check` and `vp run test` pass before the next item starts. The full suite (`vp run check`, `vp run test`, `vp run e2e`, `vp run build`) runs once after the last item.
