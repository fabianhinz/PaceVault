Changes without UI

N1Engine: calculateSummaryStress

New pure function that computes load from stored fields (duration, avg HR, NP) and thresholds. The order is TSS (NP and FTP > 0), then TRIMP (avg HR), then duration. NP 0 W with an FTP gives TSS 0. calculateTSS takes NP instead of records. calculateSessionStress now always derives NP from records, delegates to the new function, and returns NP whenever it exists.

src/packages/engine/stress.ts:7-24, 48-54, 116-143, 156-171. Test: tests/packages/engine/stress.spec.ts covers TSS, TRIMP, duration and TSS 0 at 0 W.

N2Import always stores the app's NP

The hasPowerRecords gate and the device normalized_power fallback are gone. Import computes NP from records and calls calculateSummaryStress, the same function the recompute uses, so a fresh import never "changes" on the next run. To observe: import a power file with no FTP; normalizedPower is set and the load is TRIMP.

src/parsers/fit.ts:176-180, 215. Decision: "From then on the import always computes app NP".

N3Keep rule removed from reprocessing

The reparse now keeps its own tss / stressMethod / normalizedPower. Before, it kept the stored values unless both sides were TSS. The records-only path uses sessionStressAt with records NP, or the stored NP when the records have none. With no profile, the stored values stay. SESSION_REPROCESSING_LOCK is now exported.

src/features/sessions/reprocessSessions.ts:21, 39-54, 71-84. Tests updated in tests/features/sessions/reprocessSessions.integration.test.ts.

N4Store action applyRecomputedTrainingLoad

Assigns only tss, stressMethod and normalizedPower on the immer draft, by id, so a concurrent markSessionSeen survives. The persisted shape is unchanged, so there is no version bump.

src/store/sessions.ts:36-39, 49, 92-103. Test: tests/features/sessions/recomputeTrainingLoad.integration.test.ts checks that the run keeps isNew: true.

N5Recompute and trigger

recomputeTrainingLoad() takes the reprocessing web lock, rehydrates sessions, diffs every session against sessionStressAt, and opens the overlay only for a non-empty diff. It commits every REPROCESS_BATCH_SIZE, flushes, and returns the number changed. It reads no records. The effect runs it on the first phase === 'done' after start and whenever trainingLoadSignature(profile) changes (gender and the rest HR / max HR / FTP histories).

src/features/sessions/recomputeTrainingLoad.ts, src/lib/sessionStress.ts, src/features/sessions/hooks/useTrainingLoadRecomputeEffect.ts. Integration test: a TRIMP ride becomes 64 TSS after saveTodaysThresholds({ ftp: 250 }), with getSessionRecords mocked to throw, and the result is persisted.

N6E2E seeds store a consistent load (deviation)

The seed helpers wrote tss: 80, stressMethod: 'trimp' without an avg HR. The startup heal rewrote that to the duration load and opened the overlay in the middle of the mobile bottom-sheet tests. Seeds now store the load the app itself computes. The labs/coach seed gets FTP 250 plus an NP with (NP/FTP)² × 100 = the requested TSS, so the coach tests keep their TSS 50 / 200 baselines.

e2e/helpers/seed.ts:17-30, 143, 182, 250, 264.

How to check

  1. First start on this branch with existing data: "Migrating your sessions…" appears once, for at least 1.5 s. Reload: it does not appear again.
  2. Remove the FTP (or start fresh without one) and import power rides: the load tile on the session shows TRIMP.
  3. Add an FTP in Settings: the overlay shows briefly, the tiles switch to TSS, and the dashboard fitness chart and load change.
  4. Change max HR: only sessions from today on change. Older sessions keep their load, because dated thresholds apply from today.
  5. Change gender: every TRIMP session changes, because gender is undated.
  6. Reload after any of these: nothing changes again and no overlay appears (idempotent).
  7. With intervals.icu connected, an intervals.icu ride behaves the same as a file import.
