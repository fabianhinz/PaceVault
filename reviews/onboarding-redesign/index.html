Review of plans/onboarding-redesign.md (round-5 mockup). Flow B, one question per screen, over the live H1 map: logo loader → intro → Source · You & heart rate · Bike · Import. Same steps and data as before. Built on top of the uncommitted training-load recompute. Everything is in the working tree; nothing is committed.

Deviations from the plan

  1. Preview camera fit runs at the reveal, not under the loader, and does not wait for the map's load event. The card and the dialog it pads against only mount at the reveal, so the fit runs one frame after it (duration: 0). Waiting for load (which waits for tiles) made the draw-in play at the default Europe view on a slow basemap; maplibre's camera works before load. src/features/map/hooks/useOnboardingPreviewCameraEffect.ts:43-68. The mapLoaded parameter the plan implied is not used.
  2. Energy: the heart-rate method is skipped without a gender (energy.ts:146), in addition to the per-interval guard the plan named. The guard alone would sum to a 0 kcal estimate, which breaks "0 is data, missing is missing". Blockers (weight/age) still win, so today's UI is unchanged.
  3. Loader stroke dashes follow the mockup: stroke-dasharray: 1 2 with offsets 1.05 → 0 → −1.05, not 1 with 1 → 0 → −1. The extra 0.05 hides the round caps when a stroke is empty.
  4. Intro logo is <img src="/logo.svg"> (32 px), not inline SVG markup. Only the loader inlines the paths (it has to animate them).
  5. Small additions: ActionTile.description is optional (gender rows have no caption); source and gender tiles carry role="radio" + aria-checked through the existing buttonProps; HR/FTP inputs show the mockup placeholders 52 / 186 / 240; the phone pill carries data-layout="onboarding-pill" so the camera can measure it; onboardingProgressOf / ONBOARDING_FLOW_STEPS in the store feed both "n/4" and the pill.
  6. Demo handler location: startOnboardingDemo lives in OnboardingFlow.tsx (as planned) and reaches the intro and the source step as an onDemo prop, so neither imports the flow (no import cycle).
  7. Training-load recompute code was not touched. The only shared file is src/components/ui/ImportProgressOverlay.tsx (one class swap to overlayClass, line 134).

Open points for your review

  1. Phone camera does not refit between steps. As planned it refits only on close/reopen. The "You" step is taller than the source step, so part of the preview can sit under the card (compare p-en-04-source vs. p-en-06-you-error). Options: (a) keep; (b) also refit on step change. Recommendation: (a), the map is pannable and the card is dismissible.
  2. Pill covers the expanded map attribution at 390 px (bottom right, see p-en-07-pill). Options: keep, or lift the pill above the attribution row.
  3. Cross-field HR error shows twice. With max HR 40 the existing validation shows "Min 120 bpm" under max HR and "Resting HR must be less than max HR" under rest HR (d-en-06-you-error). This is today's useThresholdsForm behaviour, more visible now that both fields sit together. Not changed (scope).
  4. "PaceVault" in the intro is a hard-coded brand string, not a message key.
  5. Focus is not trapped in the non-modal phone card (known risk in the plan); Tab can leave it.
  6. Demo banner still says "test data" / "Testdaten" (ui_demo_banner_text), as the plan noted. Follow-up, out of scope.
  7. E2E flakes under parallel load: in the first full run e2e/mobile/map.spec.ts:480 (known) and :281 failed; both passed with --workers 1, and the second full run passed 83/83. :281 is the same WebGL-picking class as :480.

How to check it yourself

  1. Clear site data and open the app: the logo grows and retracts for at least 3 s; with CPU throttling a second cycle finishes before the hand-off, and the logo is empty when it fades.
  2. The routes draw in (green runs, orange rides, no blue), framed clear of the card (desktop) or the dialog (phone). Pan and zoom work; track hover/click does nothing.
  3. Intro: the crumb line wraps without a leading "·" (DE at 390 px); "Open source" opens GitHub in a new tab.
  4. Get started → each step shows "n/4"; Back works on every step; Continue on step 1 needs a pick, on step 2 a gender and both HR values.
  5. intervals.icu path: source → you → bike → key → import → the camera fits your tracks. FIT path: the same, then Upload FIT files.
  6. Demo from the intro and from the source tile: the import overlay runs, then the demo banner shows.
  7. Phone: drag the map with the card open (it stays); tap or drag the grabber (pill "Continue setup · n/4"); tap the pill (same step, values kept, camera refits); Escape closes it.
  8. Settings → Thresholds: gender offers only Male / Female. Settings → Data: typing a key doesn't move the key field.
