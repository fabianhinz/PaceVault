Dynamic efforts

Review of plans/dynamic-efforts.md (round-4 mockup). A fourth lap source, Efforts, detected from the record stream (V2: PELT edges on 5 s bins, labels against FTP / threshold pace / HR reserve), with one summary chip, a profile nudge and the <count> <source> pill grammar for every source. Built on top of the uncommitted training-load recompute and onboarding redesign; their code is untouched. Everything is in the working tree; nothing is committed.

Deviations from the plan

  1. Extra exported constants. EFFORT_EDGE_TRACE_S (the 5 s trace the edge refine searches, mockup DEF.*.edge), EFFORT_MAD_SCALE (0.6745, Hampel) and EFFORT_SIGNAL_LIMITERS (power → ftp, pace → thresholdPace) are named constants per engine CLAUDE.md. Values are the mockup's. effortDetection.ts:58-71.
  2. Moving time from the break mask. The mockup tracks bridge lists per block; the port counts non-break seconds in each block instead. Same result, and it stays correct if an edge refine moves a boundary next to a bridge. effortDetection.ts:413.
  3. endIndex is the record at the next block's start when blocks touch (shared boundary, like splits), else the last record before the break, so stop and gap records belong to no block. effortDetection.ts:675-676.
  4. FTP or threshold pace ≤ 0 counts as missing (sets limitedBy), so the engine never divides by zero.
  5. SIGNAL_LABELS lives in lapLabels.ts (next to effortChipLabel, its only user) instead of LapsControl.tsx. LIMITER_LABELS is in LapsControl.tsx as planned.
  6. effortWorkSet (exported from effortLaps.ts) is the work-only view used for the summary row and its fastest / slowest (decision Q1); effortWorkCount uses it.
  7. Picker memo. The effort result reuses current only when current.efforts is set, not on source === 'efforts' alone, because the session set lags one render behind a source switch. The splits memo passes thresholds: undefined (unused for splits) so a profile edit doesn't rebuild it.
  8. Test id laps-efforts-row on the efforts row (used for the captures; harmless).
  9. Capture data. The brief said the demo sessions have no structured intervals; they do (see O2), but their warm-ups come out as work, so the captures use synthetic sessions instead (see Verification).

Open points for your review

  1. O1 · DE detect nudge truncates on desktop. "FTP eintragen, um Belastungen zu erkennen" needs ~245 px, the line has 240 px in w-80; it ends in "erke…" (C3). Phone fits. Options: keep (plan: truncate is the safety net), shorten the DE string (e.g. "FTP eintragen zum Erkennen"), or drop the line's pr-2. Nothing changed.
  2. O2 · Demo data with the plan defaults. Run over all 233 demo sessions: 6×800 m Isar, 5×1 km Isar, 3×2 km tempo and Sweet spot 3×12 find their reps, but the warm-up is labelled work (demo warm-up pace is faster than 0.88 × threshold speed of 5:00/km = 5:41/km), so the chip shows a count, not the pattern. Hilly demo rides (Lago di Tenno climb, Passo San Giovanni loop) give 10–20 climb "efforts". Easy runs, long runs and flat rides find none. Follow-up: tune the demo persona or the defaults.
  3. O3 · HR edges stay late on slow HR. On the synthetic run without threshold pace the HR blocks read 2:29 against 3:00 true (min work 120 s, fixed 30 s shift). This is expected and why the chip says "≈".
  4. O4 · Whole-tree vp check fails outside this feature. Oxfmt can't parse reviews/onboarding-redesign/index.html:438 (double quotes inside an alt), which stops the format step before it starts. I didn't touch it (out of scope). Fix the alt text, or add reviews to fmt.ignorePatterns next to mockups (vite.config.ts:28). vp check src tests e2e messages passes.
  5. O5 · Hot-path check. Measured in Node, not in DevTools: 1.6–3.5 ms per 2.7–3.3 h session including lapBands, far below the ~84 ms laps baseline.

How to check it yourself

  1. Open an interval ride with power and FTP set: Laps pill → the Efforts row shows "N × m:ss · power"; pick it, the pill reads "N efforts", chart bands match the reps.
  2. Device laps / Splits in the pill read "12 device laps" / "6 splits" (DE "12 Geräterunden" / "6 Splits"); Off reads "Laps".
  3. Settings → remove FTP: the row falls back to "… · heart rate ≈" with "Add FTP for precise efforts", which opens Settings.
  4. A power-only trainer ride without FTP: disabled "No efforts found" with an active "Add FTP to detect efforts". An endurance ride: "No efforts found", no link.
  5. A run without threshold pace: the threshold-pace nudge.
  6. Pick a block on a chart: the stepper steps through Work / Rec / Steady and the warm-up names (DE: Einfahren vs Einlaufen); "Gleichmäßig 12" fits.
  7. Summary card: the laps row counts work blocks only and names fastest / slowest "Work n".
  8. Engine only: vp test -- --run tests/packages/engine/effortDetection.spec.ts tests/lib/effortLaps.spec.ts.
