# Component Architecture Rules

- **Layout**: App components live in `src/components/`: one folder per feature (`components/<feature>/`, entry `index.tsx` when a page mounts it as a unit) and shared UI in topic groups (`charts/`, `metricLabel/`, `importProgress/`, `errors/`, `layout/`). Code only one feature uses lives in its folder; UI-only shared helpers live with their component owner; `src/lib/` holds only what store, queries, mutations, microcopy and routing also need, in topic folders. No `index.ts` barrels; non-UI folders get no index, importers address the declaring file. Rules: `docs/conventions/tdr/helpers-split-by-reachability.md`.
- **Hook placement**: A hook lives in the `hooks/` directory of the concept it is about, at whatever depth owns that concept (`components/sessions/session/hooks/` beside `components/sessions/hooks/` is correct), camelCase and named after the hook (e.g. `useDashboardChartZoom.ts`). A directory holds either a `hooks/` subdirectory or loose `use*` siblings, never both. Server reads and writes are not feature hooks: they live in `src/queries/` and `src/mutations/`.
- **Colocate store subscriptions**: Do not hoist store reads in parent components just to pass them down as props. Let child components subscribe directly to the store via hooks to prevent unnecessary re-renders.
