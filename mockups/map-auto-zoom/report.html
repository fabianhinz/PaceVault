Map auto-zoom audit

PaceVault, branch chore/housekeeping, 2026-10-13. Every place the map camera moves without the user panning or zooming it directly. All entries are inferred from code (static analysis); nothing was observed in a running browser.

Root cause behind most jarring entries: there are only three camera hooks (useMapCameraEffect.ts:18-72, useLapCameraEffect.ts:34-50, useGeolocationCameraEffect.ts:11-27). The first two re-fit whenever an array or object reference changes, not when the user asks for a new view. tracks is rebuilt on every change to the sessions store, GPS data, filter, opened session or trip focus (useMapTracks.ts:86), and GPS data is re-read after every sessions change (useGpsBackfill.ts:61). So one data change usually means two fits. No fit checks whether the user has moved the map: every re-fit throws away a manual pan or zoom. Every fit is animated (800–1200 ms), and a second call in the middle of an animation starts the easing again, which shows as a stutter.

Worst offenders

  1. Background data changes re-fit the map. An intervals.icu poll, an import batch, a reprocess or opening an unseen session all change the sessions store, which leads to a re-fit and then a second one after the GPS reload. It happens on any page and undoes manual pans. useMapTracks.ts:86, useGpsBackfill.ts:61
  2. Opening a session first aims at the wrong track. openedSessionId changes before the tracks reload, so the first fit goes to tracks[0] of the overview list. A second fit corrects it a few ms later. useMapCameraEffect.ts:37-50
  3. Opening a trip zooms out to all tracks, then back in. fitAll flips before the trip tracks load, so the first fit covers the union of every filtered track. useMapCameraEffect.ts:56-57, TripDetailPage.tsx:22-27
  4. Going back from a session or trip moves twice and forgets the earlier view. The first fit uses the stale single-track list, the second jumps to the densest cluster. useMapCameraEffect.ts:54-71
  5. A selected lap gets re-fitted, or lost, on unrelated changes. Changing the colour mode, weather arriving or any sessions change rebuilds the detail path, so the lap is fitted again. A sessions change also triggers a whole-session fit, which wins the race. useSessionDetailPath.ts:85, useLapCameraEffect.ts:50
