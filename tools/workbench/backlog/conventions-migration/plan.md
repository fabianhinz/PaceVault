## Approach

1. **Baseline (before the first plan):** `item-implement` captures the "before" screens (list under Delivery), records the baseline of `vp run test` (files/tests per package) and runs the conventions check `node tools/workbench/backlog/conventions-migration/research/conventionsCheck.mjs docs/conventions` (index rebuilt from `tdr/*.md` identical to `docs/conventions/CLAUDE.md`, every plan's `tdr_reference` and `depends_on` resolve, no cycle; `--write` rewrites the index).
2. **One plan at a time, in `depends_on` order** (topological; ties alphabetical), `tooling.md` last. One `item-worker` per plan, sequential: plans edit overlapping files (`useMapCameraEffect.ts`, `DeckGLOverlay.tsx`, the kit), so no two run at once. Each worker reads the TDR, then the plan, executes every Changes item and its Check, finds code by symbol where a line number has moved, then runs `vp run check`, `vp run test`, `vp run e2e`, `vp run build`.
3. **A plan is done when** its Checks and the four commands pass; the worker deletes the plan file (handover §1) and appends to `review/progress.md` (plan id, items done, deviations). A value-sensitive refactor is pinned by a temporary spec first and the pin is deleted inside the same plan (handover rule).
4. **Open or unsure points never block:** the worker keeps today's behaviour for that spot, adds an `OP-<n>` entry to `conventions-follow-ups/research/open-points.md` (what, user impact, options) and continues. A decision it makes on its own that changes behaviour, look or scope goes to `review/decisions.md`.
5. **A failing suite the worker cannot fix within its plan** (not listed in `tools/workbench/backlog/flaky.md`): the worker reverts that plan's changes, records an `OP` entry and the run continues with the next plan whose dependencies are done; plans depending on the reverted one are skipped and listed in `review/progress.md`.
6. **TDRs stay fixed during implementation.** A rule that turns out wrong becomes an `OP` entry, not a TDR edit.
7. **After the last plan:** `docs/conventions/plans/` is empty and removed; the conventions check passes; the 11 gates are on; `vp run check`, `vp run test`, `vp run e2e`, `vp run build` pass on the final tree; the review doc is built.
