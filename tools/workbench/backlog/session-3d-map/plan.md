# 3D map on the session details page

## Context

A 2D / 3D switch on the session details page. Today the session map is flat (pitch and rotate off, `apps/web/src/features/map/MapBackground.tsx:86-88`) and deck.gl draws the track, laps and chart dot (`apps/web/src/features/map/DeckGLOverlay.tsx:202-274,352-371`). 3D drapes the session on Mapterhorn terrain with MapLibre's own layers; 2D and the overview map stay exactly as they are. Proven in `mockup/` (`maps.js`: 3D layers, pick, fit ease, orbit).

## Decisions (settled)

- **Scope:** session detail page only; 2D session map exactly as today (deck.gl, today's flags, box zoom, double-click zoom, dot jumps) except the new zoom-out limit below; overview map untouched (Q34, Q35, Q26, Q56).
- **Zoom-out limit (2D and 3D):** on the session page the minimum zoom is the session's fit zoom − 2 (session bounds + page padding at pitch 0, computed without moving the camera); it never clamps: if the current zoom is already lower, the current zoom is the limit. Set after the session arrival fit, kept across view switches, cleared whenever the session is left (Q56, replaces Q35's "no zoom-out limit" and Q18's 3D-only limit). Replay, studio, box-zoom removal and GPU e2e are other items (`session-replay`, `studio-3d-map`, `disable-box-zoom`, `e2e-gpu-rendering`; Q32).
- **Control:** "Map view" pill after Color by and Laps, built like Color by: pill shows the current mode "2D" / "3D", popover (drawer on phone) "Map view" / "Kartenansicht" with radio items 2D "Flat map" / "Flache Karte" and 3D "Terrain from Mapterhorn" / "Gelände von Mapterhorn"; lucide `Box` icon (Q34, Q36, decisions.md).
- **Always available:** 3D can be switched on online and offline; no disabled state, no availability check. Offline, cached DEM tiles are used and missing tiles render flat; going offline in 3D stays in 3D (Q42 replaces Q7, Q43).
- **Default:** 3D off; per visit, not persisted (Q6). Switching between 2D and 3D never moves the centre or the zoom: only the pitch eases (30° into 3D, 0° back to 2D), and going back to 2D also eases the bearing to north (Q54, Q55; replaces the decisions.md line "leaving 3D fits the session"). Leaving the session while in 3D eases pitch and bearing to 0 and keeps centre and zoom (Q45).
- **Live position and pick circle in 3D:** the deck.gl geolocation dot and accuracy circle are hidden while 3D is on (Q44); 3D has no pick circle (Q49).
- **Code style:** new code follows the adopted conventions in `docs/conventions/` (`microcopy/` copy maps, `FC<Props>`, one options object, theme tokens for colours, `createMock*` test data) (Q46, Q48, Q50).
- **Record loading:** `useSessionDetailPath` stays in `DeckGLOverlay` (2D unchanged); `SessionTerrain` calls it again, so records load a second time only while 3D is on (Q47).
- **Terrain:** Mapterhorn `raster-dem` (`https://tiles.mapterhorn.com/{z}/{x}/{y}.webp`, terrarium, 512 px, maxzoom 16), `setTerrain` exaggeration 1, black/white hillshade at low opacity, only while 3D is on (Q2, Q5, Q11, Q15). Credited by an `attribution` on the source linking `https://mapterhorn.com/attribution` (Q41).
- **Camera in 3D:** entry tilts to 30° around the current centre at the current zoom and bearing (Q37, Q54); max tilt 60° (Q33); free rotate and tilt with right-drag and two fingers (Q17, Q31); no presets (Q34).
- **Track in 3D:** MapLibre `line` layers, one GeoJSON feature per record segment (`tolerance: 0`, feature `id` = path vertex index, mapped to the record through `DetailPath.recordIndices`), per-record colours identical to today's; min 3 px (Q12, Q14 a1 for 3D only); deck.gl draws nothing session-related.
- **Laps in 3D:** hover/casing/selected/dim through `setFeatureState` and paint expressions, never a source rebuild on lap change; a click on the track selects the lap (25 px box, closest stretch wins, same toggle as 2D), beside the track and double-click do nothing (Q40, Q28, decisions.md); lap select frames the lap at the current pitch and bearing (Q29).
- **Fit ease in 3D:** own per-frame `jumpTo` ease (ease-in-out cubic, 800 ms lap / 1.2 s session) interpolating centre, zoom, pitch, bearing and ground height; target from `cameraForBounds` without moving the map; ground height from the DEM once its tiles have settled (missing tiles read as 0 m, the height they render at), median record elevation only when the DEM has not settled within 500 ms; a gesture cancels it (decisions.md, Q42, Q53).
- **Padding in 3D:** passed per fit, transform padding stays 0, same as 2D (Q52).
- **Line layers:** a generic draped-line layer (path + per-vertex colours, pick → vertex index) with the session's laps, lap state, lap pick and hover dot as a session-only add-on, so `studio-3d-map` can reuse the line (Q51).
- **Orbit in 3D:** Shift / Ctrl / Cmd + left-drag orbits around the point under the cursor, 0.4°/px turn, 0.3°/px tilt; a move that would put the map centre more than 20 km from the pivot is rejected; box zoom off in 3D only (Q23, Q25, decisions.md).
- **Chart dot in 3D:** jumps, as in 2D (Q39).
- **Offline:** service-worker `CacheFirst` cache `mapterhorn-dem` like `carto-tiles` (Q16).

### 5. Camera

The camera effect owns pitch, bearing, padding and min zoom in both views; `SessionTerrain` never touches the camera.

- `apps/web/src/lib/mapCamera.ts:1-8,60-108`: the session target carries `view: MapView`; a view change on the same session pends `'tilt'` (camera only: no bounds, no `cameraForBounds`); arriving at any target from a session target whose view was `'3d'` (leaving the session, direct switch to another session) pends `'flatten'` unless the arrival already pends a fit. Lap and lap-close fits as today. New pure `sessionMinZoom({ fitZoom, currentZoom })` = `min(fitZoom − 2, currentZoom)` (never clamps).
- **Padding, one home:** the page padding (`mapPadding(...)`) is passed per fit as `options.padding` in both views; the transform padding stays 0 always (never `setPadding`), so nothing needs clearing on leaving 3D and `cameraForBounds` never adds a second padding (it adds `tr.padding` to `options.padding`, `maplibre-gl/src/geo/projection/camera_helper.ts:157,187-188`).
- **Every non-3D fit** in `apps/web/src/features/map/hooks/useMapCameraEffect.ts:57-69` passes `pitch: 0, bearing: 0` (`fitBounds` keeps the current pitch otherwise; a no-op today), so delete, Edit in Studio or a session switch after 3D never leaves the map tilted.
- **Zoom-out limit (Q56):** after the session arrival fit ends (`moveend` of that fit, 2D), the effect computes the fit zoom with `cameraForBounds(sessionBounds, { padding, bearing: 0 })` (pitch-independent, the map does not move) and calls `setMinZoom(sessionMinZoom({ fitZoom, currentZoom: map.getZoom() }))`. View switches, lap fits and lap-close fits keep it. Whenever the target stops being that session (overview, trip, studio, another session, `'flatten'`), `setMinZoom(null)` runs before anything else; the next session's arrival sets its own.
- `apps/web/src/features/map/terrainCamera.ts` (new, topic module): `ENTRY_PITCH = 30`, `PITCHED_ZOOM_OUT = 0.4` (3D lap and session fits only), durations as unit-named ms constants (no `MS_PER_*` module exists in `packages/engine/src/`): `DEM_SETTLE_TIMEOUT_MS = 500` (Q53), `LAP_FIT_DURATION_MS = 800`, `SESSION_FIT_DURATION_MS = 1200`, `TILT_DURATION_MS = 800` (entering 3D, back to 2D, `'flatten'`); `terrainTiltTarget({ map, pitch, median, settled })` (current centre, zoom and bearing, the given pitch, ground height at the centre via `fitGroundHeight`); orbit constants; pure `interpolateTerrainCamera({ from, to, progress })` (ease-in-out cubic, centre weight `(1 − 2^(−Δz·e)) / (1 − 2^(−Δz))`, bearing the short way round), `medianElevation(elevations)` (nulls skipped, 0 kept), `fitGroundHeight({ settled, terrain, median, current })`; `whenTerrainSettled({ map, timeout })` → `Promise<boolean>`; `terrainFitTarget({ map, bounds, pitch, bearing, padding, maxZoom, median, settled })`; `easeTerrainCamera({ map, target, duration, onEnd })` (one `jumpTo` per animation frame incl. `elevation`, centre clamping off for its duration, a `movestart` with `originalEvent` cancels; `onEnd` runs only when the ease completes; returns a cancel function).
- **Ground height:** `queryTerrainElevation` returns 0, not `null`, where no DEM tile is loaded (`maplibre-gl/dist/maplibre-gl-dev.js:67995-68000,68599-68607`), so "loaded" is checked separately: `whenTerrainSettled` resolves `true` as soon as `map.getTerrain()` is set and `map.isSourceLoaded(<dem source>)` is true (errored tiles count as finished, `maplibre-gl/src/tile/tile_manager.ts:151-163`), else `false` after `DEM_SETTLE_TIMEOUT_MS`. A failed tile fires `error`, never `sourcedata` (`maplibre-gl/src/tile/tile_manager.ts:191-197` vs `:313`), so the check re-runs on `sourcedata`, `error`, `terrain` and `idle` and once per animation frame until the timeout; offline, errored tiles settle at once and the 0 m ground is used, not the median. `fitGroundHeight`: settled → the queried height (0 m where tiles are missing = the flat ground they render, also offline); not settled → the median record elevation of the lap or session; no median → the current elevation. One owner: `terrainFitTarget` takes `median` and `settled`, queries the terrain and calls `fitGroundHeight`. "Settled" covers the tiles in view; at a lap's higher zoom `queryTerrainElevation` reads the loaded parent tile (`getSourceTile(tileID, true)`, `maplibre-gl/src/render/terrain.ts:246`), a coarser height but not 0 m.
- **Fit order on entering 3D:** `SessionTerrain` mounts in the same commit as the view change, but `useMapCameraEffect` runs in `DeckGLOverlay`, an earlier sibling, so its effect fires first. The `'tilt'` into 3D therefore awaits `whenTerrainSettled` (which first waits for `setTerrain`), then builds `terrainTiltTarget` and runs `easeTerrainCamera`, interpolating pitch and the ground height at the fixed centre, so the view does not jump as the relief appears; a newer fit or a gesture during the wait drops it (fit token). Lap fits await it too (usually already settled, no delay).
- `apps/web/src/features/map/hooks/useMapCameraEffect.ts:57-69,94-99,141-147`: one options parameter `{ gpsData, tracks, lapPath, sessionPath, mapLoaded }` (`DetailPath`s for the median); in 3D `'session'`, `'lap'` and `'lapClose'` go through `terrainFitTarget` + `easeTerrainCamera` (lap: current pitch and bearing, max zoom 16, `LAP_FIT_DURATION_MS`; session: current angle, `SESSION_FIT_DURATION_MS`). `'tilt'` is handled before `fitBoundsOf` and never blocked: into 3D as above (`ENTRY_PITCH`, `TILT_DURATION_MS`); into 2D `easeTo({ pitch: 0, bearing: 0, duration: TILT_DURATION_MS })` keeping centre and zoom (no `fitBounds`, Q54, Q55); the zoom-out limit stays. `'flatten'` is handled before `fitBoundsOf` too (`apps/web/src/features/map/hooks/useMapCameraEffect.ts:132-140`, which returns on `bounds === null`, and `sessionBounds` is null once the session is left): `setMinZoom(null)`, `easeTo({ pitch: 0, bearing: 0, duration: TILT_DURATION_MS })` keeping centre and zoom, then settle (Q45). `mapCameraFitBlocked` (`apps/web/src/lib/mapCamera.ts:146-149`) returns `false` for `'tilt'` and `'flatten'` (camera only, no session data), so a delete or an import overlay does not hold it back. A running ease is cancelled by the next fit and on unmount.
- `apps/web/src/features/map/zoneColoredPath.ts:12-16,50-60,62-74`: `DetailPath` gains `elevations: Array<number | null>` (record `elevation`, `null` when missing), filled in `validPath` and passed through `buildColoredPath` (`:73`) and `buildSportColoredPath` (`:111`); `apps/web/src/features/map/lapPath.ts:52-56` slices it.

## Risks

- MapLibre 5.18 `easeTo` on terrain samples unloaded DEM tiles as 0 m (camera under the mountain, or drift growing with height): every 3D fit uses the own per-frame ease; 2D keeps `fitBounds`.
- Padding per fit with transform padding 0 differs from the mockup, which kept the page padding on the map: the perspective now centres on the canvas, not the free area, so a pitched lap on desktop (wide right panel) may frame a little off (Q52). Fallback if the real-data check fails: the page padding on the transform as in the mockup, eased in and out with the 3D fits. Check the Lechlauf laps against the mockup; never `setPadding` before a fit (that alone jumps the camera).
- `queryTerrainElevation` returns 0 m, not `null`, without a loaded DEM tile: the fit waits for the DEM source to settle (≤ 500 ms); after the timeout the median record elevation is used and can be off once the relief arrives.
- Lap highlight through `setData` / `setFilter` lags the camera by a few frames (GeoJSON worker); feature state shows the next frame.
- Rebuilding the track source on a lap change froze one frame for ~195 ms (M5, 37,800 records): lap changes only touch feature state and the `line-color` paint property.
- Entering 3D costs one ~120 ms frame on an Apple M5 (37,800 segment features + terrain); phones unmeasured.
- Without `tolerance: 0` the few-metre segments vanish at session zoom.
- Mapterhorn publishes no usage policy (Cloudflare-sponsored); the SW cache limits repeat requests, a self-hosted PMTiles copy is the fallback.
- Two code paths for track, laps, pick and dot (deck.gl in 2D, MapLibre in 3D): a change to one must be mirrored in the other.
- `disable-box-zoom` turns Shift+drag box zoom off in 2D too; whichever lands second resolves `boxZoom` in `apps/web/src/features/map/MapBackground.tsx`.
- Touch tilt pivots at the map centre, not between the fingers (MapLibre `TwoFingersTouchPitchHandler`).
- Offline with partly cached tiles: missing tiles render flat at 0 m next to cached relief (steps at tile edges).
- The 3D tilt starts after the DEM settles (up to 500 ms after choosing 3D) rather than at once.
- The tilt keeps the 2D centre and zoom (Q54): zoomed far in on steep terrain, the 30° view can sit close to the slope; zoomed out, the relief is barely visible until the user zooms in.
- The zoom-out limit changes 2D for every session (Q56): it must be cleared on every way off the session (back, delete, Edit in Studio, peek to another session), or the overview stays limited; the e2e `goBack()` check covers one way.
- The limit is set at the arrival fit's `moveend`; a gesture that interrupts that fit still sets it, from the bounds, so it never depends on where the fit stopped.
- `pitchWithRotate` becomes `true` for the map's lifetime (react-map-gl 8.1 applies it only at construction); 2D stays unpitchable only because `dragRotate` and `touchPitch` are off there.
- A second record load while 3D is on (Q47).
